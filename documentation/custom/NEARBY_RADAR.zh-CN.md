# 附近设备雷达

两个独立入口：`Apps → Bluetooth → BLE Radar`（文件 `nearby_radar.fap`）和 `Apps → WiFi → WiFi Radar`（文件 `wifi_radar.fap`）。两版使用相同的简洁流程，分别只请求 BLE 广播或 Wi-Fi 接入点扫描，不再显示混合列表或切换模式的按钮。应用由 Flipper 显示列表及目标信号变化，扫描由连接的 ESP32 配套程序完成。官方手机 App 可通过屏幕遥控操作；这不是手机独立扫描器。

## 找设备

1. ESP32 必须运行本仓库 `companion/nearby_radar` 中的 NR1 配套程序，并使用已确认的 UART 接线与供电。应用启动后自动按 Momentum 的 ESP UART 设置连接，速率为 115200；无需先进入串口配置页。
2. 收到握手及 RUN 确认后自动扫描并列出附近设备。没有配套板时显示 `Waiting for ESP32` 或 `No ESP32 response`，不会填入演示设备；此时长按右键可切换 USART/LPUART 重试，串口被占用时 OK 重试。
3. 列表先显示扫描到的名称，默认按信号从强到弱排列。最上面是接收信号最强的观察，**不能保证物理距离最近**；没有广播名称时显示 Unnamed BLE / Unnamed WiFi，可在详情里看地址。上下选名字，按 OK 打开目标雷达页。
4. 长按 OK 输入名称或地址片段，忽略英文字母大小写。过滤条件也发给配套板，避免密集环境中无关观察占满列表。清空搜索框可恢复全部。
5. 雷达页只保留设备名、两个圆环、平滑后的 RSSI 和 Stronger/Weaker/Steady。走动时比较趋势；按 OK 查看地址、无线类型、Wi-Fi 信道及最后观察时间，按 Back 返回雷达。圆点位置只表达相对信号强弱，**没有方位和米数含义**。
6. 超过 12 秒没有观察到目标，圆点隐藏、读数变成 `-- dBm` 并显示 Lost signal；列表中超过 60 秒未出现的观察不再列出。左键暂停/恢复扫描；目标页按 Back 返回列表，列表再按 Back 退出并停止串口扫描会话。

本机键盘输入英文及数字；中文 SSID 可从列表选中，显示受设备现有字库限制，也可按地址片段筛选。名称来自设备主动广播的数据，可能为空、重复或变化。BLE 私有地址变化后作为新观察处理，不推断它和旧地址属于同一设备。

## 能发现什么

- BLE：正在广播且能被接收的设备，名称取自广播。不开启主动扫描请求、不建立 GATT 连接，不保证每个耳机、手机或其他电子设备都可见。
- Wi-Fi：参考 ESP32 支持的 2.4 GHz 接入点，显示 SSID/BSSID、信道与接收信号。扫描列表不是路由器的已连接客户端清单，也不证明某个设备是摄像机。
- 最多保留 32 条观察，名称上限 32 字节，UART 行和缓冲均有界。选中的目标不会因其他观察到达而被替换；异常帧不会当成设备数据。

信号受天线朝向、遮挡和反射影响；Stronger 只表示接收信号增强，不保证实际距离缩短。

## 配套板与构建

`companion/nearby_radar/platformio.ini` 固定 PlatformIO espressif32 6.10.0，为普通 ESP32 开发板提供可编译的参考环境。里面的 UART RX/TX 是参考配置，**不是已验证的 AIO Board 1.4 接线**。实际板卡芯片、UART 引脚及供电须在实物接入后确认；不能按三合一板名称直接刷写。

参考环境为 4 MB Flash，使用框架自带的 `huge_app.csv` 分区（3 MB 应用、无 OTA 双分区），以容纳 Wi-Fi 与 BLE 协议栈。不同容量的实际板卡需要相应分区配置。

已有 Marauder/Ghost ESP 等固件不实现 NR1 协议。参考程序是独立固件，刷入会替换 ESP32 原程序；本轮未执行板卡刷写。后续应先识别现有固件，再决定适配现有输出或使用参考程序。

参考程序只被动接收 BLE 广播、被动扫描 Wi-Fi 接入点，不连接接入点、不广播模拟外围设备、不控制被观察设备。Flipper 定期发送存活消息；10 秒没有收到有效控制消息时配套板停止扫描。BLE 扫描分片最长约 2 秒，停止命令可能等待当前分片完成。

## 串口协议 NR1

所有帧为 ASCII，LF 结尾，CR 可忽略。设备名称以原始字节的大写十六进制表示，避免逗号和控制字符破坏帧边界。

- 控制：`NR1,HELLO`、`NR1,PING`、`NR1,SCAN,A`（全部）、`NR1,SCAN,B`（BLE）、`NR1,SCAN,W`（Wi-Fi）、`NR1,STOP`。
- 名称/地址筛选：`NR1,FILTER,<名称片段的十六进制>`，空字段清除筛选。
- 握手：`NR1,R,ESP32,BW`；状态：`NR1,S,RUN` 或 `NR1,S,STOP`。
- 观察：`NR1,D,<B或W>,<12位十六进制地址>,<RSSI>,<信道>,<名称十六进制>`。BLE 的信道字段为 0；RSSI 必须为 -127 到 -1。

## 验证边界

自动测试编译实际 `radar_core.c`，检查分帧、损坏和超长帧恢复、同名/同地址不同无线类型、名称/地址筛选、信号趋势、超时、计时回绕、容量上限和选中目标保留。额外使用两份应用清单中的编译参数运行实际扫描命令函数，确认 BLE 版发 `NR1,SCAN,B`，Wi-Fi 版发 `NR1,SCAN,W`。两份 Flipper FAP 与参考 ESP32 固件还需分别构建。

用户确认 AIO 板当前未连接，因此实际扫描、串口引脚、接收灵敏度和手机遥控链路仍需实物验收。自动测试和没有板卡时的启动检查不能替代这些验收。
