# Wi-Fi 与蓝牙增强：现状和实施顺序

日期：2026-10-01。本页以当前仓库源码为准，区分已构建的代码、已刷入的版本和仍需实物验收的能力。

## 已有基础

- Flipper 本机没有 Wi-Fi 射频；Wi-Fi 扫描依赖外接板及其固件。仓库中的 `[ESP] WiFi Scanner` 使用 ESP8266 专有串口协议，不能因为 AIO Board 1.4 含 ESP32 就认定兼容。`[ESP32] WiFi Marauder` 也要求板上运行与应用匹配的固件。
- `Lab Bridge` 是通用 UART 收发桥，已有有界缓冲、丢失计数和蓝牙 RPC 读数。本次将本机接收默认端口改为 Momentum 的 ESP UART 设置，增加 USART/LPUART 手动切换与当前端口显示；手机 RPC 的端口选择和协议没有改变。它能帮助识别板卡是否在指定端口输出数据，但不能解释未知固件的协议。
- 标准蓝牙串口、RPC、文件及屏幕遥控路径保留。官方 iPhone App 能走标准连接与遥控接口；在线应用目录是否列出某个私有 FAP，仍受官方清单和 UID 规则限制。自建中文手机端已有断线后有限次数重连，且不会自动重发未完成的设备操作；该手机端目前暂停继续开发。

## 下一批可验收的增强

1. **蓝牙实机兼容验收**：用 iPhone 官方 App 验证配对、重连、文件列表、启动已安装应用和屏幕遥控；逐项记录固件／App 版本与失败步骤。先修复发现的具体兼容故障，不预改无线协议。
2. **AIO 板识别**：读取实物芯片丝印、现装固件、供电与 UART 引脚，用 `Lab Bridge` 分别检查配置端口和另一端口的接收计数。收到字节仅证明有串口输出；须再确认输出格式，才接入专用 ESP32 扫描页。
3. **被动 Wi-Fi 勘测**：在确认的 ESP32 固件上采集接入点的 SSID、BSSID、信道、RSSI 和加密方式；保存带时间戳的扫描结果，做信道占用和信号变化比较。现有手机离线解析器能导入受支持的 ESP32 扫描日志；实物采集、导出和长时间稳定性尚未验收。
4. **连接诊断**：报告蓝牙连接阶段、失败原因及串口丢失计数；测量真实传输速率和断线恢复。RSSI 是接收功率，不直接代表距离；须在固定位置与多次重复条件下比较。

`BLE Spam` 的 11 个模式在 `applications/external` 上游子模块内，当前没有修改其广播参数或协议。2026-10-01 查到[上游开发分支的应用清单](https://raw.githubusercontent.com/Next-Flip/Momentum-Apps/dev/ble_spam/application.fam)仍标 `6.6`，与本地清单相同；仅更新版本号不能解决逐模式兼容和实测问题。若继续整理，可逐模式补充兼容性说明、可见的运行状态、明确的停止操作和退出后恢复检查。源码中的键盘锁需要连续三次 Back 解锁，而第一次 Back 尚未立即停止应用自身广播；这是应优先修复的可控性问题。上游子模块不能仅改本地文件就作为本仓库的更新发布，须有可追踪的下游源码版本或补丁集。

## 验收边界

当前固件仍为 `ee43b2c2`（源码 `52f236fd`）。本次新编译的 `Lab Bridge` FAP 已通过 USB 安装到 `/ext/apps/Tools/lab_bridge.fap`，设备端 MD5 与本地一致；启动、左右键输入和退出的 USB 冒烟测试通过。AIO Board 1.4 的芯片、固件与 UART 引脚未确认；官方 iPhone App 的 BLE 真机连接和 ESP32 扫描均未通过实物验收。有关标准 App 的限制见 [官方 App 兼容范围](OFFICIAL_APP_COMPATIBILITY_20260930.md)，串口操作见 [扩展板串口说明](../../mobile/FlipperLab/SERIAL_BRIDGE.zh-CN.md)。
