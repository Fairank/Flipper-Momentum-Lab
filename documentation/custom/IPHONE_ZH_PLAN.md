# iPhone 与 Flipper 中文协作方案

评估日期：2026-09-24。源码快照：`b06c940ec326fef33954b49cffbc085f16607aaf`。

## 目标与当前交付

用户已确认：以 iPhone 为优先手机端，开发新的手机软件，利用手机算力增强 Flipper；设备端功能也要重写，并提供中文界面及功能介绍。

本次完成仓库检查、分工设计、功能说明初稿和验收规划。下文的产品名称、模块边界与开发顺序是建议；App、协作模块和中文固件尚未实现，未生成 IPA 或新的固件安装包，也未进行真机连接。此前三个固件改动的历史结果见 [VALIDATION.md](VALIDATION.md)。

## 仓库实际情况

仓库是 Momentum 固件的个人定制，原分支为 `codex/momentum-unleashed`。已记录的改动包括应用资源加载进度、插件扫描容错和构建源文件顺序去重。主仓库已跟踪文件中没有 Swift 源码或 Xcode 工程；本次未递归下载子模块，不能据此推断外部子模块的全部内容。

| 已检查的位置 | 源码结论 | 对新方案的影响 |
| --- | --- | --- |
| `targets/f7/ble_glue/services/serial_service.c` | BLE 串口服务包含收发、流量控制和 RPC 状态特征，并设置认证访问要求 | 手机端需处理配对、订阅、流控与断连，不能只实现一次连接 |
| `applications/services/bt/bt_service/bt.c` | BLE 字节流已接入 RPC | 第一版沿用现有通信基础 |
| `applications/services/rpc/rpc.c` | 使用带长度前缀的 protobuf 编解码 | BLE 分包边界不等于消息边界，客户端必须持续组包 |
| `applications/services/rpc/rpc_app.c` | 已有 DataExchange 双向字节数据接口；待确认命令只有一个槽位 | 应用命令串行发送，确认后再发下一条；长任务另用任务号跟踪 |
| `applications/services/rpc/rpc_app.h` | 数据交换事件需要显式确认，事件指针仅在回调内有效 | 异步处理前复制有界数据，不持有回调中的临时指针 |
| `targets/f7/api_symbols.csv` | 数据交换、回调设置和确认函数已导出 | 可以先验证独立协作应用，再决定是否扩展系统服务 |
| `applications/main/infrared/scenes/infrared_scene_rpc.c` | 已有文件加载、按钮控制、会话关闭及退出时停止发送流程 | 已保存红外遥控可先接现有接口；手机触发采集仍需单独实现并验证 |
| `applications/services/gui/canvas.c` | 已调用 UTF-8 绘制接口，也支持主题覆盖字体 | 中文还需要覆盖汉字的字库与字体回退，不能只改字符串 |
| `applications/services/gui/modules/text_box.c`、`applications/services/gui/elements.c` | 部分宽度计算和换行逐字节处理字符串 | 中文排版需按 Unicode 字符边界改造和回归 |
| `lib/momentum/asset_packs.c` | 主题字体按整个文件读入内存 | 不宜直接放入完整大字库；先评估子集字库与内存预算 |
| `.gitmodules`、`SOURCE_LOCK.json` | protobuf 来自 Next-Flip 分支，固定提交为 `ea4f185f5eaa265955c520eae2832887ee6aa5e4` | 手机与设备应使用同一锁定协议，不能直接替换成官方最新版本 |

以上是源码检查结果，不是硬件运行结论。可从 [固定源码快照](https://github.com/Fairank/Flipper-Momentum-Lab/tree/b06c940ec326fef33954b49cffbc085f16607aaf) 复核。

## 双端分工

建议把产品做成“iPhone 工作台 + 中文 Flipper 固件”。手机承担大数据处理和丰富交互，设备保留离线能力与硬件实时控制。

| 层次 | 职责 | 首版建议 |
| --- | --- | --- |
| iPhone 工作台 | 中文导航、搜索、资料库、图表、任务记录、离线帮助 | SwiftUI 原生应用；建议先以 iOS 17 为最低版本，实际型号确认后再定 |
| 手机计算 | 脉冲统计、重复片段检测、已知协议候选匹配、日志筛选和记录比较 | 先提供可解释的规则与统计；模型识别作为后续可选功能 |
| 通信层 | 配对、连接状态、RPC 编解码、流控、能力协商、取消与重连 | Core Bluetooth + 仓库锁定的 protobuf |
| Flipper 应用层 | 中文菜单、设备状态、采集工作流、协作任务、离线操作 | 分模块重写用户操作与任务逻辑，复用并审查成熟驱动 |
| Flipper 实时层 | 射频/红外收发时序、NFC/RFID 交互、GPIO 与本机停止操作 | 留在设备上；手机下发任务参数，不经 BLE 逐脉冲控制 |
| 扩展板 | 型号相关的采集与通信能力 | 型号与协议明确后接入；先预留能力描述 |

手机增强的是处理、存储和操作体验。可用频段、采样方式和实时响应仍取决于 Flipper 与扩展硬件；不能把手机算力描述为提升射频带宽或让未知协议自动可用。

重写范围建议覆盖本机首页、主要功能入口、说明页、任务状态与手机协作接口。内核、启动/恢复链路及各硬件驱动先作为稳定基础，只有具体问题或新能力需要时才更换。保留 Momentum 的主题、动画和已有应用兼容目标，逐项验证，不承诺未经测试的兼容性。

## 第一版完整流程

优先做自有红外遥控的整理与分析：

1. iPhone 配对设备，读取固件、协议版本和可用能力；未连接时可离线阅读指南。
2. 用户在 Flipper 上采集信号并保存；第一步先支持导入已保存文件，随后增加手机触发采集。
3. iPhone 获取文件，检查格式和完整性，保留原始数据及来源。
4. 手机统计脉冲时长、比较多次采集、寻找重复片段，展示有证据支持的协议候选及无法判断项。
5. 用户添加中文名称、房间和设备分组，保存到手机资料库。
6. 用户选择已有遥控按钮，经现有 RPC 控制 Flipper 执行；设备显示执行状态并可在本机停止。
7. 在手机和 Flipper 上提供相同功能的中文说明：作用、准备事项、步骤、结果含义和能力限制。

红外脉冲包络不等于直接测得载波。界面需要区分原始观测、文件元数据、规则推断和模型推断，不能把文件字段或猜测显示成测量结果。

## 手机界面与功能介绍

建议使用五个入口：**设备、工具、资料库、任务、指南**。

- 设备：连接/配对状态、电量、存储、固件及兼容性；明确显示未连接、连接中、准备完成、忙碌和失败。
- 工具：按用途展示功能，每项有一句用途说明和“使用方法”；未具备的能力显示原因。
- 资料库：原始记录、中文别名、标签、搜索、对比、导出和备份。
- 任务：当前阶段、进度、取消、真实结果和失败原因；断连后先查询状态再决定重试。
- 指南：离线中文说明，与固件能力对应，不能把路线图当作可用功能。

配套的 [中文功能目录](FEATURE_CATALOG.zh-CN.json) 是内容初稿，所有新增产品功能标为 `planned`。它不是设备探测结果。将来以稳定功能 ID 关联实际能力和帮助内容，手机使用完整说明，本机使用短说明与关键步骤。

## 通信与任务约定

先保持现有 BLE 服务和顶层 RPC 协议，验证在协作应用中使用 DataExchange 的可行性。不能假定任意现有应用都支持自定义消息，也不能假定协作应用与现有前台应用可同时占有硬件。

第一阶段优先用已有存储 RPC、系统信息和应用控制。第二阶段再定义应用层消息：版本与能力查询、任务创建、状态查询、取消、结果索引。应用层字段应包括协议版本、任务 ID、请求 ID、操作、状态和结构化错误；它们属于待实现的设计，不是现有固件 API。

必须满足以下要求：

- 组包、重试与队列均有明确上限。遵守设备流控和 Core Bluetooth 当前可写长度；源码中的特征最大值不能当作所有 iPhone 的实际分包长度或吞吐率。
- 第一版应用命令只保留一条等待确认。确认表示请求已受理或被拒绝，长任务完成另发结果，不能混淆两者。
- 数据回调做长度与版本校验，把需要的内容复制到有界队列后再异步处理；繁重运算不放在 BLE/RPC 回调中。
- 大记录优先保存在 SD 卡，以文件或有界分块获取。摘要可以实时传输，完整数据分批分析。
- 断线后查询任务状态。具有外部作用的操作不能盲目自动重放；重复请求的处理规则要明确。
- 取消、本机返回键和通信丢失后的资源释放都需验证。对持续输出设置设备端期限，并保证不依赖手机持续在线才可停止。
- iOS 后台运行受系统调度限制。首版长分析任务以前台为主要路径，数据可保存后恢复；蓝牙后台模式不视作无限持续计算保证。

当前源码中 RPC 缓冲配置为 1024 字节，BLE 串口特征数据长度上限定义为 486 字节；这些是实现参数，不代表实测吞吐率，也不直接等于应用消息允许长度。最终限制需结合编码开销、缓冲方式和真机测量确定。

## 本机中文化工程

1. 建立稳定字符串 ID 与中英文资源，菜单、设置、错误、状态和帮助统一用词。
2. 对选定页面生成小范围汉字字库；评估 12/16 像素字体的实际可读性、固件大小和 RAM 占用。
3. 修改涉及中文的换行、裁剪、滚动、光标与字符串测量逻辑，保证不在 UTF-8 多字节中间截断。
4. 主题不含中文时采用可用字体回退；字体或 SD 资源缺失时仍能显示基本操作和恢复提示。
5. 本机放简短说明，手机放完整指南。协议名称、文件格式键名和程序标识保持兼容，仅翻译展示文案。
6. 中文别名优先保存在手机元数据中；是否启用设备中文文件名，需先验证文件浏览、传输和外部应用兼容性。
7. 全面中文覆盖分阶段扩展。启动与恢复界面的中文化独立评估，不能把一批菜单翻译描述为完整中文固件。
