# 手机算力与扩展板：2026-09-27 状态

用户已选择先完成代码和自动测试、以 MIFARE Classic 离线样本作为首个密钥分析范围。本页记录当前实现，不替代真机验收。

## 已实现并自动验证

- [Classic 离线工作台](../../mobile/FlipperLab/CLASSIC_OFFLINE.zh-CN.md)：两组认证数据的密钥恢复、候选字典双样本验证、多个字典合并去重、复核结果加入字典、导出。恢复不需要先提供字典，普通 `.nfc` 转储不能代替认证样本。
- C 引擎每次约 17 MiB 临时空间，工作量和输入均有限制，可取消；独立 Swift 实现再次检查结果。公开已知答案、生成样本、错误输入、取消与 iPhone 界面已通过自动测试。
- Wi-Fi 已保存扫描日志的多网络离线分析，以及 NFC/RFID/iButton 文件字段查看与记录比较。
- [串口接收桥](../../mobile/FlipperLab/SERIAL_BRIDGE.zh-CN.md)：UART → Flipper Lab Bridge → 蓝牙 RPC → 手机。包含限长缓冲、丢失计数、停止和断连资源释放、原始数据导出。C/Swift 协议测试、iOS 与固件构建通过。

## 尚待实物验证

- 用户 AIO Board 1.4 的厂商、芯片、固件、端口、波特率和供电尚未核实。参考资料中的 ESP32、CC1101、nRF24 不代表实物已经识别；三个模块不能视为同一种无线设备。
- iPhone 17 Pro Max 与 Flipper 的配对、文件一致性、串口端到端实时数据、持续接收和异常恢复均未测。模拟器没有蓝牙，不能替代这些检查。
- 用户自有 Classic 样本的恢复结果仍待验证。没有声称可恢复所有 NFC 密钥，也没有把结果转换为 iPhone 可刷的门禁凭证。

## 未实现

未知 AIO 固件的专用实时扫描协议、CC1101/nRF24 新驱动、任意串口命令手机入口和定向 Wi-Fi 断链控制均未完成。板卡不输出串口数据时，通用接收页面不会生成或伪装实时结果。
