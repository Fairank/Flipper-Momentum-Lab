## 第二阶段：硬件信息与实用升级评估

以下是后续调研表，不是已实现功能清单。用户所说的“WiFi 终结者”可能对应不同设备或项目；不能默认等同于某个 Marauder、ESP32 型号或特定软件。

| 待确认项 | 需要记录的信息 | 确认后评估的方向 |
| --- | --- | --- |
| Flipper Zero | 当前固件/API、SD 卡、主要使用场景 | 设置兼容、应用整理、备份与恢复 |
| ESP32 板卡 | 精确型号、芯片、Flash/PSRAM、接线与电源、固件版本 | 串口连接状态、日志、模块重连、版本匹配、升级恢复 |
| “WiFi 终结者” | 产品名/项目链接、板卡型号、当前固件、与 ESP32 是否同一设备 | 是否已有兼容 Flipper 应用、通信协议和重复功能 |
| 其他已有模块 | 型号、接口、电压、电源及现有应用 | 引脚冲突、供电稳定性、驱动适配与统一配置 |

可在自有或获授权的测试设备上优先评估连接诊断、网络扫描结果整理、信道与信号显示、日志导出、板卡固件版本提示、断连恢复和功耗。具体支持哪些能力，须以实物和项目文档为依据。此轮未增加或测试 Wi-Fi 功能。

## 第三阶段：软件候选项

这些建议最初来自 Xtreme 代码抽样阅读，不能直接断言 Momentum 存在相同问题；开始实现前先核对当前 Momentum 实现。

| 候选方向 | 下一步 | 验收依据 |
| --- | --- | --- |
| 文件搜索范围、类型过滤、分页 | 测量大目录耗时与内存，再决定是否需要索引 | 固定数据集上的耗时、内存、取消与翻页行为 |
| 设置保存失败反馈和恢复 | 核对 Momentum 写入链路，再设计临时文件/备份 | 空间不足、写入中断和恢复场景结果 |
| 中文菜单与帮助 | 先做小范围字库、排版和内存验证 | 真机可读性、字符覆盖和资源占用 |
| 红外遥控整理 | 根据常用自有设备设计分组与检索 | 日常操作步骤减少且格式兼容 |
| 串口日志/GPIO 工具 | 先确认板卡连接和已有应用 | 连接、记录、导出与断连恢复可用 |
| 12 小时时间格式边界 | 先核查 Momentum 是否仍有 Xtreme 的正午 AM 问题 | 00、11、12、13、23 点边界结果 |
| 持续跟进上游 | 逐项比对 Momentum/Unleashed 提交与 API | 记录来源、兼容性、回归及是否已被上游实现 |

实施顺序：完成现有构建验证 → 确认硬件和最常用场景 → 选择一个小项 → 验证后再扩展。当前无需一次做完。
