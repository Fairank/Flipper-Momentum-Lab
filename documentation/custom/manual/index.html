学习自己的遥控器

可识别协议会保存结构化信息，未知协议可能保存 RAW 脉冲。保存成功仍需要实际验证家电响应。

空调通常把温度、模式和风速一起编码，普通按键复制不一定表达全部状态。索引列出了美的、三菱和日立等专用遥控器。

  1. 打开 Infrared → Learn New Remote。
  2. 原遥控器对准 Flipper 顶部，按一下要学习的按键。
  3. 识别后按提示保存，为按键命名；继续添加其他按键。
  4. 从 Saved Remotes 打开记录，对准自己的家电并选按键测试。

遇到问题

学不到时检查原遥控器电池、是否使用红外、方向与强光干扰。响应不对时检查品牌、协议与状态。蓝牙遥控器和无线射频遥控器不是红外。

手机不会提高红外发射功率。官方屏幕遥控可以尝试操作同一设备界面；独立中文遥控页不会自动出现在官方 App。

04 NFC、RFID 与 iButton

先识别卡型。高频 NFC、低频 RFID、UHF RFID 和接触式钥匙使用不同硬件与协议。

对象与条件

入口对象与硬件
NFC13.56MHz 高频卡；本机 NFC，读取能力受协议与认证限制。
125 kHz RFID125kHz 低频卡；本机低频天线，不是 NFC。
UHF RFID 应用超高频标签；需要应用指定的外部 UHF 读头。
iButton接触式电子钥匙；与设备背部触点可靠接触。

读取自己的 NFC 测试卡

Read 是读取，Saved 是保存记录，Add Manually 是手工创建，Extra Actions 是额外工具。Extract MFC Keys 是 MIFARE Classic 认证样本相关功能，不是通用一键解密。

Emulate 是设备模拟，Write 是写入支持且可写的标签。模拟 UID、模拟完整数据和通过实际读卡器验证是不同结果。

手机离线分析代码针对有必要认证样本的 MIFARE Classic 流程，任意 .nfc 文件不自动具备足够信息；官方手机端没有自动获得这套工作台。

当前没有把任意门禁卡导入 iPhone NFC 并直接当门禁使用的功能。蓝牙传文件不等于手机能模拟该卡。

  1. 打开 NFC → Read，把卡贴近设备背部，保持稳定。
  2. 查看卡型、UID、协议和未读取区域；记下实际结果。
  3. 按提示 Save 保存，从 Saved 打开文件查看。
  4. 只有 UID 时，不要解释成完整复制；进一步分析需要卡型和实际获得的数据。

低频卡和接触钥匙

125 kHz RFID → Read：自己的测试卡靠近背部，识别后保存；Saved 查看记录。写入前确认空白标签与协议。T5577 应用不是所有低频卡的通用写卡工具。

iButton → Read：钥匙与背部触点接触，读到后保存。接触不稳定会失败。索引还列出了格式转换工具。

NFC/RFID Detector 用于区分读头产生的场，不代表读出了卡内容。Metroflip、Passport Reader 等只解析各自支持的格式。

观察自己的遥控器

帮助列出的常见频段为 300-348、387-464、779-928MHz；实际能力还受模块、协议、地区与配置限制。外接 CC1101 需要正确供电、引脚与模块选择。

滚动码每次发送可能变化，保存一次不保证重放有效。频谱图只是支持频段的能量信息，不能直接列出 Wi-Fi 终端或确认某个设备是摄像机。

本手册不提供滚动码绕过、批量触发设备或解除发射限制的操作步骤。

  1. 查看自己遥控器标注的频率，或用 Frequency Analyzer 观察。
  2. 回到 Read，按界面设置匹配频率，按自己遥控器的按键观察协议和数据。
  3. 无法识别时可保存 Read RAW 波形，用 Sub Analyzer / ProtoView 离线查看结构。
  4. 保存并记录型号、频率和结果；接收成功不代表完整复制或稳定控制。

06 GPIO 与 AIO 三合一板

当前 AIO Board 1.4 的厂商、芯片、切换方式与板端固件未确认，不能只凭板名宣布全兼容。

模块分别负责什么

模块作用与条件
ESP32 / ESP8266Wi-Fi 等由芯片与板端固件提供；Flipper 应用通常是串口控制界面。
CC1101相应 Sub-GHz 信号，不负责 Wi-Fi。
NRF24（需确认）相应 2.4GHz 协议；之前写的 nrf244 尚未核实，不直接认定型号。
各类传感器需要应用指定硬件；无线三合一板不自动具备照度、温度、盖革管或相机。

串口和 GPIO

GPIO → USB-UART Bridge 让电脑经 Flipper 与串口外设通信；GPIO Manual Control 是引脚手动控制。UART Terminal 是扩展串口终端。

接线以板卡资料为准。常规 USART 示例为 TX13、RX14，TX 接对方 RX，地线相连，使用兼容逻辑电平。插头可插入不证明供电与引脚正确。

波特率与板端一致；Expansion Modules 的 Listen UART、系统日志和板卡应用可能占用同一串口，需要核对。

Lab Bridge 的范围

通用 UART 数据通道有缓冲上限、序号和状态检查，配套自建手机端能接收与导出原始数据，并报告丢失或截断。它不是未知 AIO 固件的 Wi-Fi、CC1101 或 NRF24 专用驱动。

官方 App 不会自动出现实时数据页。板卡不输出数据时，空白界面也不能证明周围没有网络。AIO 真实链路未验收，后续应先用已知字节和校验值做端到端验证。

Wi-Fi 和摄像机能判断到哪一步

WiFi Scanner 等应用显示兼容 ESP 模块给出的接入点扫描结果，不等于路由器全部已连接设备。自己的网络终端清单优先在路由器管理页面查看。

摄像机可能用网线、本地存储或休眠；厂商标识与流量只能提供线索，不能确定是否录像。没有本机能统一识别的“录像专属辐射”。

第三方 ESP 工具已有各自测试模式；本手册仅说明用途与硬件条件，不含定向或多网络断链、干扰、钓鱼和凭据采集步骤。

07 官方手机 App 控制

目前优先适配官方 Flipper App；自建中文 iPhone App 代码保留，界面开发暂停。

标准配对与遥控路径

这是标准路径说明，兼容结论来自固定官方源码检查；这台设备与官方 iPhone App 的真实配对、传文件、遥控和断连恢复尚未验收。

Remote Control 显示设备英文屏幕；官方 App 自身语言由其版本决定。手机浏览器可以打开本手册搜索中文。

  1. 设备 Settings → Bluetooth 设为 ON；手机开启蓝牙并允许官方 App 使用。
  2. 在 App 内选择设备，按两端提示确认配对验证码。
  3. 打开 Remote Control，用方向键、OK、Back 操作普通界面。
  4. 进入设备 Apps / Archive 找实际文件。USB、GPIO 和切换蓝牙模式的应用单独验收。

为什么手机目录不是全部应用

官方应用目录依赖安装清单和线上条目，不递归扫描所有 .fap。私有应用与多层分类可能不出现在列表，随意补清单也不保证可用。

通用入口是 Remote Control → 设备 Apps / Archive → 实际文件；需要 API 匹配、资源完整和正常按键处理。切换 HID 等蓝牙 profile 的应用可能中断当前遥控。

USB Remote、U2F 和 USB 存储仍需 Flipper 连接目标 USB 主机；手机蓝牙不能替代数据线。

Misc 中 Dolphin 是海豚选项，Screen 是屏幕，VGM 是 Video Game Module；Spoof 改变部分展示标识，不能代替真实 API 和硬件信息。普通使用先保留协议默认值，优先整理主菜单、快捷键与收藏。

locale_ui_label 当前返回英文，locale 服务只处理单位、日期和时间格式，没有全局界面语言状态。一个快捷键不能自动翻译所有现有应用。

全局切换还需语言设置、持久化、快捷键动作，以及原生页、第三方应用、动态文案和图片内文字逐项接入。部分中文入口不能称为全覆盖。
