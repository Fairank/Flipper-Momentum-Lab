# 扩展板串口输出到 iPhone

入口：**功能 → 扩展板实时数据**。本轮实现的路径是：扩展板 UART 输出 → Flipper `Lab Bridge` → Flipper 蓝牙 RPC → iPhone。手机显示收到的数据和丢失计数，并可导出原始二进制记录。

## 使用条件

1. 安装包含 `Lab Bridge` 的配套固件和应用资源；编译产物为 `apps/Tools/lab_bridge.fap`。
2. 核对 AIO Board 1.4 实物的端口、波特率、接线和供电。不能仅凭板名确定这些参数；软件不会自动开启 GPIO 5V，也不会刷写板卡。
3. 手机连接 Flipper 后，在实时数据页面选择 USART/LPUART 和匹配的波特率，再开始接收。UART 已被其他应用占用时明确报错。
4. 板卡必须实际输出串口数据。页面空白只能说明尚未收到数据，不能由此判断 Wi-Fi 环境、板卡是否存在或板卡固件种类。
5. 在手机停止接收后导出记录。离开页面或进入后台会停止；连接异常会断开并释放设备串口。

此页面提供接收与导出，不提供任意串口命令输入。它不是针对未知 AIO 固件的 Wi-Fi 扫描、CC1101 或 nRF24 专用驱动，也没有实现定向 Wi-Fi 断链控制。

## 数据完整性

- 设备缓冲 8 KiB，每次最多读取 512 字节；请求和回复按序号、操作类型及长度核对。
- 手机保留最近 64 KiB 原始数据，屏幕显示末尾 8 KiB。屏幕按文本显示不能替代原始二进制导出。
- 分别报告设备丢失和手机截断；硬件串口溢出只能统计事件，所以设备丢失计数是下限。不能把截断记录当成完整抓取。
- 协议包含版本、状态码、端口与波特率限制；所有缓冲均有上限。具体线格式见 `Sources/FlipperCore/SerialBridge.swift` 与 `applications/main/lab_bridge/bridge_protocol.h`。

## 当前验证

`0d741468` 已通过 Swift 协议及缓冲测试、真实 C 请求校验测试、iOS 模拟器编译和界面入口测试、完整固件构建。没有连接用户的 Flipper、iPhone 或 AIO 实物，因此**端到端实时数据、吞吐量、长时间接收、断线恢复和实际供电仍待真机验收**。

后续实物验收应先发送已知长度和校验值的普通串口测试数据，比较手机导出字节；再测试空数据、连续数据、缓冲溢出、停止和断连。记录实际板卡固件、端口、波特率与丢失计数，不以模拟数据冒充板卡结果。
