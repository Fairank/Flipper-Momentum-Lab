# MIFARE Classic 离线分析

入口：**功能 → NFC 离线工作台**。数据在手机本地计算，不上传云端。支持 MIFARE Classic 的两组认证样本；普通 `.nfc` 卡片转储不是这种样本，其他 NFC 协议不能套用此方法。

## 已实现

- **密钥恢复**：不要求先提供字典，从两组认证数据反推 Crypto1 状态并恢复候选 48 位密钥，再用独立 Swift 实现复核两组数据。
- **字典验证**：导入候选密钥，逐项复核两组认证数据，显示扇区、Key A/B、CUID 和命中的密钥。
- **增强字典**：合并多个字典、统一为 12 位大写十六进制、稳定去重，并将已复核的结果加入字典后导出。不是生成无法验证的随机密钥。
- 可取消任务，离开页面或 App 进入后台时取消。恢复失败、资源上限和取消均不标成成功。

## 输入与上限

每行采用 Flipper `.mfkey32.log` 的 `Sec … key … cuid … nt0 … nr0 … ar0 … nt1 … nr1 … ar1 …` 格式。标签、字段长度和扇区范围均检查；两组认证必须不同。最多 64 组去重样本、单个文件 2 MiB。

字典每行一个 48 位密钥，支持连续十六进制或六组一致分隔的字节、完整行 `#` 注释及空行。最多合并 8 个文件，每个文件 2 MiB，合并后最多 100,000 个不同密钥。非法行报告行号，导入失败保留此前材料。

恢复算法每次约使用 17 MiB 临时空间，计算量有上限；不保证所有卡片或所有样本都能恢复。普通卡片转储、缺失认证字段、采用不同认证方式的样本不能代替所需输入。

## 自动验证与实物边界

内置示例明确标为 Proxmark3 公开测试向量。`0d741468` 的 [macOS/iOS CI](https://github.com/Fairank/Flipper-Momentum-Lab/actions/runs/36301957045) 已通过真实 C 恢复、Swift 双样本复核和 iPhone 模拟器界面操作。桌面 C 测试另覆盖四组生成样本、错误认证数据、重复数据和计算中取消；Linux 同时使用地址和未定义行为检查器。

这些结果证明离线计算实现可运行，不是用户实物卡片的验收。没有连接卡片或采集新的认证数据，也没有向卡片写入密钥。结果不能直接变成 iPhone 或 Apple Wallet 门禁凭证。

算法来源与 GPL 许可说明保留在 `Sources/ClassicRecovery/recovery.c`；公开向量来源为 [Proxmark3 自测](https://github.com/RfidResearchGroup/proxmark3/blob/master/tools/pm3_tests.sh)。
